03 / Compute allocation

What it does and why it is better: GPU nodes move between prefill and decode as the agent workload changes.

03-DTwo clusters

The same agents feed a fixed cluster and Evolving Infra. When the agents change, the fixed cluster builds a waiting line while some of its nodes idle. Evolving Infra turns the idle decode nodes into prefill nodes.

Open ↗ 03-EReversible lanes

Each GPU node is a lane. When traffic shifts toward prefill, Evolving Infra turns decode lanes around, like reversible lanes at rush hour, while the fixed road backs up.

Open ↗ 03-FMoving wall

Work falls onto prefill and decode nodes. Behind a fixed wall one side piles up while the other side idles. Evolving Infra slides the wall so both sides stay busy.

04 / KV cache management

What it does and why it is better: keep the context that agents come back to, drop what nobody reuses.

04-DWho gets forgotten

The same agents fill the same memory twice. Existing systems drop the agent that waits for a tool, which must then recompute. Evolving Infra drops what is done, so the agent resumes at once.

Open ↗ 04-EKeep the right branches

A context tree grows as agents work. When memory is full, Evolving Infra cuts the faded branches that nobody will reuse, while LRU cuts the branch of the waiting agent, which then has to regrow.

Open ↗ 04-FSkip the line

The agent’s context sits on a busy GPU node. Existing systems make the agent wait in that node’s line. Evolving Infra sends it to the free node and brings the context along, so it starts sooner.
