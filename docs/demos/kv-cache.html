Animation of two trees of context in the KV cache, one for an existing KV manager and one for Evolving Infra. Agents A and B build up context, and B forks C. A waits for a tool. C finishes and B compacts its history, so no active branch needs their old KV. B needs room for new context and the cache is full. The existing KV manager evicts in LRU order and drops the KV of A, so when the tool returns, A recomputes its context. Evolving Infra evicts the KV that no active branch needs, so A reuses its KV.

How it works

KV directory: the router keeps a cluster-wide prefix tree of the KV in GPU and host memory of every node, and counts for each block on each node how many active agent branches reference it there. A fork or a sub-agent adds one count to each block it reuses. A consecutive request of the same branch counts only its new blocks. When compaction rewrites a context, the router releases the branch’s counts on the blocks that the new context drops. A transfer between two prefill nodes moves the branch’s counts to the target. The source copy becomes unreferenced only when no active branch references it there.

Routing and eviction: the router sends each prefill request to the node with the shortest predicted time to first token: the rest of its running batch, its queued requests, and the new request itself, each predicted by the prefill model. The prediction also accounts for fetch delay that outlasts the queue wait and the duplicate copy that a fetch creates. The selected node fetches the KV of the request from the shared KV pool while the request waits in its queue, so the fetch overlaps the wait. Each node evicts host-memory blocks with a zero count first, in least-recently-used order, and evicts blocks that an active branch still references only when none are left.

Comparison: in the report’s routing comparison, cache-aware routing concentrates requests on nodes holding their prefixes, while the Dynamo KV router can send requests to nodes that recompute prefixes. In the stationary benchmarks, the Dynamo baseline uses the SGLang Model Gateway and HiCache with LRU eviction. LRU can evict the KV of waiting branches while keeping histories that compaction replaced. On Claude Code, these evictions cause 34–46% of the KV reuse that Dynamo loses. Evolving Infra lowers the P95 TTFT by 3.25–13.92× relative to Dynamo on Claude Code and OSWorld.
